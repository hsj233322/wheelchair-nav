# wheelchair-nav

《能耗与舒适性约束下的智能轮椅动态路径规划方法研究》的可复现仿真平台骨架。

纯 Python + CPU，无 ROS、无实车。目标不是"再写一个 A*"，而是让论文里的每个数字都能追回
唯一一份配置、唯一一次运行。

## 快速开始

```bash
uv sync                 # 国内网络慢可用：uv sync --default-index https://pypi.tuna.tsinghua.edu.cn/simple
uv run pytest
uv run python -m runner.experiment configs/frozen_A.yaml scenarios/house_01.yaml
```

HouseExpo 真实户型场景（数据子集需先按 `data/README.md` 下载）：

场景质量档案汇总在 `docs/scene_metadata.csv`（每个场景一行：路径长度、房间标签变化、
房间数、连通分量数、不可达占比、clearance 分布、最宽瓶颈、地形占比、难度档）。

最后一条会在 `results/<run_id>/` 下产出：

| 文件 | 内容 |
|---|---|
| `config.json` | platform / scenario / algo 三层快照 + config hash + git commit + seed |
| `metrics.csv` | 首列为 config hash，每次重复一行 |
| `trajectory.npz` | t / xy / yaw / speed / yaw_rate / energy_j / clearance / collision |

`run_id` 形如 `frozen_A-03fba3b5-s42-20261022T144516Z`，时间戳只用于区分目录；
同一 seed 重跑，`metrics.csv` 除 `run_id` 外逐字段一致。

## 参数三层 + 执行层

| 层 | 内容 | 能否作为实验变量 |
|---|---|---|
| platform | 质量、尺寸、最大速度/加速度、传动效率、辅助功率、电池参数 | 否 |
| scenario | 地图、墙体、路面滚阻、坡度 | 否 |
| algo | 能耗预算、离障距离、曲率上限、权重、时域 | **是，唯一可变层** |
| run | seed、repeats、out_dir、dt | 不是模型参数，只被记录 |

`runner/config.py` 会拒绝：

- 三层文件里的未知字段、重复 YAML 键、缺失必填字段；
- algo 文件里出现 platform/scenario 字段（例如 `mass`）——防止"偷偷改平台"；
- `d_min < body_radius`、`v_cruise > v_max` 这类跨层矛盾。

config hash 只覆盖 platform + scenario + algo。换 seed 重跑，hash 不变；这样
"配置"与"重复"是两个维度，符合第 5 章参数治理的叙事。

## 关键约定

- **坐标**：世界单位 m；数组第 0 行对应 y 最小侧，第 0 列对应 x 最小侧；单元中心为
  `origin + (i + 0.5) * resolution`。
- **栅格化（矩形墙）**：`map.walls` 的矩形与单元有任何重叠即判为障碍（保守），
  薄墙不会漏；户型轮廓 `map.polygons` 的规则见下面「HouseExpo 轮廓」。
- **离障距离**：单元中心到最近障碍物表面的距离；地图边界外视为障碍。
- **能耗记账**：全局层用稳态巡航（`accel=0`）估算每步电能，作为硬预算；
  下坡/制动不回收（保守）。电池内阻损耗按 `I²R` 计入。
- **曲率**：8 邻域单步转角只能是 45° 的倍数，直接套 `Δθ ≤ κ·ds` 会禁止一切转弯。
  因此 A* 用**曲率窗口**：`max_turn = kappa_max * kappa_window_m`（默认 1.5 × 0.6 =
  0.9 rad，允许 45°、禁止 90°）。精确曲率由后续 `core/bspline.py` 在平滑阶段保证，
  两处共用同一个 `kappa_max`。
- **平顺性指标**：以 jerk RMS + 平均绝对角速度为主；`total_turn_deg` 只作辅助，
  不能单独用来论证"更平顺"（旧论文的坑）。
- **参考轨迹**：当前按恒定巡航速度采样、朝向受 `w_max` 限速，因此 jerk 恒为 0、
  角速度是几何量。它是链路验证用的参考轨迹，不是控制器输出；真实速度/朝向平滑
  在 DWA + B 样条里程碑补上。
- **HouseExpo 轮廓与「墙 / 门洞」的来源（2026-10-25 更正）**：`verts` 是**自由区轮廓**，
  不是简单的房间外框。它把每道内墙的两侧各描一遍，于是内墙在填充结果里表现为宽约
  **0.12 m** 的狭缝（实测 7e80c5f4：2135 条狭缝，p25 = 中位 = p75 = 0.120 m），
  **门洞就是狭缝中断处**。所以预览图里的内墙与门洞**来自 HouseExpo 原始数据**，
  转换代码没有推断它们——`env/floorplan.py` 只做一件事：扫描线填充多边形，
  单元中心在内部即自由。栅格面积与轮廓 shoelace 面积误差 < 2%
  （`tests/test_scenarios_registry.py` 有校验）。
  数据里没有独立的「墙/门」对象列表，所以下面这些量是**我们的几何推断**：
  * **房间**：`clearance >= core_clearance_m`（默认 0.9 m）作房间核心，其余自由单元
    归属最近核心（等价于对距离场做 watershed）。门洞比房间窄，因此在核心之间断开；
  * **`room_label_changes`**：路径上**房间标签**变化次数（连续 <3 格的短游程会被合并）。
    **它不等于门洞个数**：走廊若比 0.9 m 窄，走廊内没有核心，会被 watershed 按最近核心
    切成若干段。实测 `houseexpo_5427f9b0`：7 次标签变化里有 5 次发生在同一条 1.50 m
    宽的走廊上（该走廊 clearance 恒为 0.750 m < 0.9 m）。论文里引用时必须按这个口径写；
  * **`interface_widths_m` / `min_interface_width_m`**：每次标签变化处分界面上的
    `2 x max(clearance)`，同样可能包含走廊切段，只作参考。
- **不依赖房间分割的硬指标**（推荐作为论文主指标）：
  * `clearance_min_m` / `clearance_p10_m` / `clearance_median_m`：路径 clearance 的最小值 /
    10% 分位 / 中位数；
  * `clearance_below_090_ratio`：路径上 `clearance < clearance_threshold_m`（默认 0.9 m）
    的**路段长度占比**（按单元间长度加权）；
  * `bottleneck_width_m`：起点到终点的**最宽瓶颈**宽度（对 clearance 做二分，
    最大连通阈值 x2）。这是"无论怎么绕都必须挤过的最窄通道"，与 A* 走哪条路、
    与房间分割都无关；
  * `bottleneck_crossings` / `bottleneck_min_width_m`：沿路径 clearance 局部极小的个数
    （`scipy.signal.find_peaks` + 显著度）与其中最窄宽度。
- **参数归属（2026-10-25 解耦）**：场景层只声明**物理**外接圆半径
  `map.inflation_m = platform.body_radius`（0.58 m，用于地图膨胀与碰撞判定）；
  **策略**安全半径 `algo.astar.d_min`（默认 0.70 m = 0.58 + 0.12 裕度）是算法层参数，
  也是实验变量，档位配置在 `config/configs/dmin_sweep/`。跨层校验只要求
  `d_min >= body_radius`（以及 `d_min >= map.inflation_m`）；调大 d_min 不再被场景拖住。
  A* 的 clearance 硬约束在数学上等价于按该半径膨胀栅格，所以场景里**不另存膨胀栅格**。
  预览图里深红带是物理半径、橙色带是物理半径到 d_min 之间的策略裕度。
- **材质空间分布是受控实验因子，不是实测材质**（2026-11-07 改口径，见下面「受控材质因子」一节）：
  HouseExpo 只有几何、没有地面材质。旧做法按房间类型映射（厨房/卫生间 → 瓷砖、
  卧室/客厅 → 木地板、走廊 → 水泥），只有 `c_rr = 0.015 / 0.020 / 0.025` 三档、
  **跨度 1.67 倍**，直接后果是能耗加权 A* 退化为 tie-break、(长度, 能耗) 前沿
  全部退化为单点。现在改成：**真实户型几何 + 按受控面积占比叠加的材质分区**，
  `c_rr` 覆盖论文材质表的四档 0.015 / 0.03 / 0.04 / 0.06（跨度 4 倍），
  分布分低阻为主 / 混合 / 高阻为主三档。**论文必须按"受控因子 + 假设"表述**，
  并配合 ±30% 敏感性与 `P_aux` 敏感性使用。
- **场景难度分档**（`env/scene_quality.py::grade_scene`）：**只看 `bottleneck_width_m`**
  —— 起终点之间"最宽瓶颈"的宽度（对 clearance 二分，取最大连通阈值 x2）。它与 A* 走哪条路
  无关、与 `algo.astar.d_min` 无关，所以同一场景在任何档位下档位标签都一样，场景表不会自相矛盾。
  阈值依据：
  * `hard`：`< 1.6 m`。1.40 m = 2 x 基准 d_min(0.70) 是最小可通行宽度，余量不足 0.2 m（两格）算难；
  * `medium`：`1.6 ~ 2.0 m`；
  * `easy`：`>= 2.0 m`，余量 >= 0.6 m（约 1.5 x 车身半径），通道基本不构成约束。
  参考量：1.16 m = 2 x body_radius（物理最小）、1.40 m = 2 x 基准 d_min（策略最小）。
  `room_label_changes` / `bottleneck_crossings` 降级为**描述性统计（路径相关）**，不参与分档。
  **分档对象**：档位标签描述的是**冻结任务**（场景自带的 start/goal，已被 content_hash 覆盖）
  的瓶颈宽度；同一栋房子不同端点对的瓶颈可以不同，所以重新采样出来的任务会**单独复算档位**
  （必须落在同一档，否则丢弃）。因此"场景档位"与"某档是否存在任务"是两个问题，
  后者要看 d_min 扫描的重采样结果（见下文）。
  采样规则：easy 在同一房间内采样且路径 ≥4 m，medium/hard 在不同房间之间采样且路径 ≥8 m，
  全部用 `core.astar` 在基准 d_min 下验证有解，并把结果按档位复核（`bottleneck_width_m` 定档），
  不达标就跳过（`config/scenario_selection.yaml`，每档多备候选）。
- **窄门组**：`narrowdoor_w080/w100/w120` 是受控门洞（0.8/1.0/1.2 m）的**合成**场景，
  供通过性实验使用。它们按 `width/2 - 一个单元` 的安全半径验证有解，并分开记录两个口径：
  `feasible_at_physical_radius`（门宽 ≥ 2 x 0.58 m）与 `feasible_at_base_d_min`
  （门宽 ≥ 2 x 0.70 m）。其中 1.2 m 门洞对物理半径够、对基准 d_min 不够——这正是
  通过性实验要测的边界，不是 bug。
- **场景内容哈希**：每个场景带 `content_hash`（sha256，不含该字段本身），
  `runner/config.py` 加载时校验；改场景内容必须重算哈希（`env/build_scenarios.py` 自动重算）。

## 相对旧代码修掉的系统性问题

| 旧代码问题 | 这里的处理 |
|---|---|
| g 累计能量 J、h 返回长度 m，启发式失效 | g 与 h 都以米计，能耗只作为资源约束 |
| 参数硬编码在类内 | 全部来自三层 YAML，core 不读配置 |
| 转角 >135° 惩罚返回 0（掉头不罚） | 转角用硬上限，不存在"越界反而不罚" |

## B 样条平滑（`core/bspline.py`，2026-10-28）

A* 输出的是**栅格折线**（步长 0.1~0.141 m，转角只能是 45° 的倍数，拐点曲率是尖峰）。
`bspline.py` 把它变成"位置 / 切向 / 曲率随弧长"的参数曲线，**但不放松任何硬约束**。

### 四个关键设计决策

1. **三次均匀 B 样条用"逼近"而不是"插值"。** 节点在 `[0,1]` 等距、首末各重节点
   `p+1` 次（clamped），因此 `C(0)=P_0`、`C(1)=P_n` —— **端点严格重合**，不做这一步
   是经典 bug。均匀节点下曲线不逐点穿过中间控制点；这一点是刻意的：先试过按弦长
   参数化解插值线性系统，A* 顶点间距极不均匀（直线段 9 m vs 拐角处 0.1 m）时会直接
   **奇异**。逼近曲线还保证整条曲线落在控制多边形凸包内，"控制点可行"即"曲线可行"。
2. **`kappa_max` 与 A* 共用，不分裂。** `algo.bspline` 段里**没有** `kappa_max` /
   `d_min` / `e_budget`——它们全部从 `algo.astar` 取（`runner/config.py::
   bspline_effective_params`），在 `bspline` 段重复声明会被 `validate_algo` **直接拒绝**。
   A* 用它做搜索侧代理约束（`max_turn = kappa_max × kappa_window_m`），平滑侧用它做
   精确校验，同一份参数。
3. **离障用距离场逐点复核，不查"是否落在膨胀栅格"。** `sample_field` 对
   `clearance_field` 做**双线性插值**，按 0.02 m 步长扫全程。实测这一步是必要的：
   `houseexpo_0df8d098` 的 A* 路径离障只有 0.7116 m（比 `d_min = 0.70` 高 **11.6 mm**），
   平滑切角后掉到 0.657 m — 只看"采样点是否在膨胀区"会漏掉这类毫米级越界。
4. **三道关口顺序固定：曲率 → 离障 → 能耗。** 能耗按**实际几何长度**重算
   （`curve_energy`，口径与 A* 的稳态巡航记账一致），超出 `e_budget` 不走"忽略"，
   而是调整控制点后重来。

### 控制点是怎么生成的（口径说明，2026-10-29 补充）

**结论先行：`control_spacing_m = 0.8` 是*目标*间距，不是实际间距。** 实测 20 个场景里
有 17 个的实际均距是 **1.5~5.5 m**，只有 3 个（RDP 后只剩 2~3 顶点的直线型任务）落在
0.77~0.79 m。图例与 `docs/bspline_report.csv` 里同时给出 `target` 与 `actual` 两列。

生成规则（`core/bspline.py`）：

1. **RDP 简化**：阈值 `rdp_epsilon_m = 0.15`（≈1.5 格）把折线压成 3~10 个顶点；
2. **`select_indices_by_arclength`**：在**这些 RDP 顶点里**按等弧长挑子集，
   目标个数 = `round(length / 0.8) + 1`（12~26 个）；
3. **`control_points_for`**：若第 2 步挑出的子集 **< 4 个**（三次 B 样条的最小控制点数），
   退化为 `resample_by_arclength` —— 沿 RDP 折线等弧长重采样，
   这时点仍落在原线段上，间距真的≈0.8 m。

**为什么实际间距会远大于目标**：第 2 步只能在 RDP 顶点里选，而 RDP 顶点数（3~10）
**少于**目标个数（12~26）。`np.unique` 去重后选出的点数就等于 RDP 顶点数，于是间距
被 RDP 顶点锁住：`length / (n_rdp - 1)`，也就是 1.5~5.5 m。

这解释了此前两张叠图的矛盾：`8bb3c35d` 是 14.41 m / 7 点 = 2.06 m（5 个 RDP 顶点
+ 2 次插入），`1241c62f` 是 9.37 m / 13 点 = 0.72 m（RDP 只剩 3 顶点，走了 resample）。

**这是已知的设计缺陷，不在本轮修复范围**（`core/bspline.py` 本轮禁改）。正确做法是
让第 2 步直接对**重采样后的等弧长点**做筛选，而不是对 RDP 顶点做筛选——这样间距才
真由 `control_spacing_m` 决定，曲率尺度也才真正可控。登记为下一轮 B 样条补强项：

- 影响：曲率尺度实际由 RDP 顶点密度而非配置决定，"0.8 m ⇒ κ≈1.25"的经验关系不成立；
- 不改变本轮任何结论：`curvature_infeasible` 的判定是**逐点实测**的，与间距取自哪里无关；
  但"调小 `control_spacing_m` 能不能救回不可跟踪任务"这个实验在当前实现下**无效**
  （调小配置不会改变控制点个数），这一点必须在论文里写清。

### 控制点调整策略（形式化）

三条约束对**控制点间距 `h`** 的敏感性方向相反，所以调整方向必须按失败关口分开：

| 调整动作 | 对离障 clearance | 对曲率峰值 κ |
|---|---|---|
| **加密**（h↓） | **升**：更贴折线，切角更小 | **升**：间距越小，转角越"尖" |
| **放稀**（h↑） | **降**：转角被切掉更多 | **降**：曲线更接近低曲率光滑弧 |

由此得到唯一自洽的规则：

| 失败关口 | 调整动作 | 理由 |
|---|---|---|
| **离障** | **加密**（插入相邻控制点中点） | 间距越小，曲线越贴折线，切角越小，clearance 回升 |
| **曲率** | **放稀** | 间距越大曲线越平滑 |
| **曲率但已到 4 点下限** | **加密** | 此时曲率过大不是"间距太小"，而是"点太少、圆化半径太大，两个拐角连成了一个大弯"；加密把大弯拆回小弯。实测 `e888f399`：4 点时 κ=2.14 仍超限，加密 1 点后降到 0.66 |
| **能耗** | **放稀** | 转角切得更多，几何长度与电能下降 |

递归深度上限 `max_insert_depth = 3`。

### `rdp_epsilon_m = 0.15` 不是随手取的数

8 邻域折线的"栅格阶梯"振幅就是**一格 = 0.1 m**。RDP 阈值若小于它，锯齿会被当成真实
几何原样保留，三次曲线穿过去后曲率直接判为不可行（0.1 m 内转 45° ≈ 7.8 1/m）。
所以默认 0.15 m ≈ 1.5 格，是**相对栅格分辨率**的量。

### 回退的定性：这是**约束违反**，不是"降级成功"（2026-10-29 修正）

深度用尽仍失败时回退到 RDP 折线。**折线在拐点处不可导，曲率无界**
（`max_abs_curvature = inf`），所以回退产物**违反曲率约束**，它：

* **不是可跟踪的参考轨迹，不得交给局部规划器**（任何有限转向能力的底盘都跟不动）；
* 只能用作"该任务在当前安全裕度下无法生成满足 κ 约束的平滑路径"的**证据**。

为此代码里拆成两个**独立**属性，任何统计都不许用一个冒充另一个：

| 属性 | 含义 | 回退时 |
|---|---|---|
| `success` | 几何链路是否产出结果 | `True`（确实产出了折线） |
| `curvature_ok` / `curvature_infeasible` | 曲率硬约束是否**真的**成立 | `False` / `True` |
| `trackable` | 能否交给局部规划器 | `False` |

`docs/bspline_report.csv` 里对应两列：`produced_spline`（是否产出样条）与
`curvature_satisfied`（曲率是否满足），**成功数不掩盖违反数**。

### 曲率不可满足统计（7.7 第 6 条，`docs/bspline_feasibility.csv`）

主指标是 `curvature_infeasible_rate`，**不是**"几何链路成功率"：

| 档位 | 任务 | 曲率满足 | 曲率违反 | 违反率 | 插入率 | 一次通过 |
|---|---|---|---|---|---|---|
| easy | 8 | 8 | 0 | **0%** | 12.5% | 87.5% |
| medium | 5 | 2 | 3 | **60%** | 80.0% | 20.0% |
| hard | 7 | 2 | 5 | **71.4%** | 71.4% | 28.6% |

机理可以用"切角深度"直接算：κ ≤ 1.5 1/m 对应最小转弯半径 `r = 1/κ = 0.667 m`，
一个 45° 转弯向内切掉 `Δ = r(1/cos 22.5° − 1) ≈ 55 mm`。

* **medium 违反的 3 个场景**，A* 离障都是 **0.7116 m**，相对 `d_min = 0.70` 只余
  **11.6 mm < 55 mm** —— 几何上无解；唯一满足的 `8bb3c35d` 裕度是 **150 mm**。
* **hard 7 个场景**瓶颈 1.46~1.50 m，`2 × d_min = 1.40 m`，可用带宽 0.06~0.10 m，
  同样小于 55 mm。满足的两个是 `5427f9b0`（19 m 直线，κ 恒 0）与 `7381e847`
  （κ=0.753），都是"低曲率需求"任务。

结论：**安全裕度越紧，轨迹平滑的自由度越小**；当
`clearance − d_min < r(1/cos(Δθ/2) − 1)` 时，任何满足 `κ ≤ κ_max` 的曲线都必然越界，
回退是唯一合法输出。这条判据给第 3 章"硬约束 vs 软惩罚"提供了**解析基线**。

## DWA 局部规划（`core/dwa.py`，2026-10-30）

输入 **`trackable = True` 的参考轨迹** + 逐帧动态障碍，输出速度指令与执行轨迹。

### 前置红线：不可跟踪的任务不进入局部规划

`dwa.reference_from_smooth` 强制校验 `trackable`；回退折线（曲率无界）直接抛
`NotTrackableError`。分析模块把它记为 `skipped_untrackable`，**不计入指标分母**，
并在报告里单列。

### 舒适性为什么一个硬、一个软

| 量 | 归类 | 理由 |
|---|---|---|
| `a_y = v·ω ≤ a_max` | **硬约束**（候选直接剔除） | 只依赖本周期 `(v,ω)`，**可解析算出**，不需要历史；是侧翻/舒适的真实物理边界，越界不是"略差"而是不可接受 |
| `jerk` | **代价项** | 三阶量，需 ≥3 个历史周期差分；做成硬约束会让同一候选的可行性随历史抖动（周期性死锁），且离散二阶差对噪声敏感 |

实现顺序强制"**先硬约束剔除，后代价排序**"。

### 绕行判据是可行性，不是加分（**2026-10-30 修正口径**）

```
required_gap(δ) = gap_overtake + 0.5(1+cos δ)·(gap_head_on − gap_overtake)   # 表面间隙要求
判定: 最小圆心距 ≥ body_radius + r_o + required_gap(δ)
                   \_________/   \__/
                    车体物理半径  障碍半径
```

**`required_gap(δ)` 的量纲是"表面距"，不是"圆心距"**，因此判据必须显式加上
`body_radius + r_o`（两圆不接触的充要条件，与 δ 无关，本平台 = 0.58 + 0.30 = **0.88 m**）：

| δ | 表面间隙要求 | 圆心距阈值 = 0.88 + 上列 |
|---|---|---|
| 迎面（δ≈0） | 0.60 m | **1.48 m** |
| 同向（δ≈π） | 0.25 m | **1.13 m** |

修正前的实现写成 `required_gap(δ) + r_o`，**漏掉车体半径**：同向阈值只有
`0.25 + 0.30 = 0.55 m < 0.88 m`，等于允许两圆重叠 **0.33 m**。实测（修正前）
预测口径的最小圆心距恰好饱和在 **0.550 m**，而执行口径的最小实际圆心距只有
**0.007 m**，36 个动态任务里 **26 个**出现过圆心距小于 0.88 m（两圆重叠）。
两条口径不能混用，见下面「圆心距的两条口径」。

`gap_head_on_m` / `gap_overtake_m` 在配置里仍是**表面间隙**，含义不变，
只是判据补上了车体半径那一项。

### 五道硬约束

1. **静态离障**：当前位置合规时未来点必须合规（否则会"从合规区走进不合规区"）；
   已不合规时只禁止**继续恶化**，否则全部候选不可行、原地锁死。
2. **动态间距**（上式，含 `body_radius + r_o`）：阈值是**圆心距**口径，
   与 `clearance`（到墙面距离）不是同一个量。
3. **横向加速度** `a_y = v·ω ≤ a_y_max`。
4. **原地自转抑制**：`|ω|` 超门限时 `v` 不得低于 `spin_speed_floor·v_nominal`。
   `a_y` 在 `v→0` 时失效，没有这条会出现"ω 打满 + 刹车"的原地打转。
   **门控必须由速度窗口决定**：若无条件生效，`ω` 打满后 `ω` 窗口锁在
   `[1.881,2.09]` 而 `v` 窗口只有 `[0,0.08]`，全部候选同时违规、车彻底锁死。
5. **终点减速带** + **到达容差 ≥ 一个周期位移**：终端是点判据而每周期位移可达
   0.1 m，否则会在终点前反复微调。

### 六个实测踩过的坑（代码注释里都写了原因）

| 坑 | 现象 | 根因 |
|---|---|---|
| `jerk` 用一阶差分 | `v` 恒为 0.08，任务跑不完 | 把**加速度**当 jerk 罚，正常起步被罚 1.2 |
| `jerk` 未归一化 | 让行后**再也起步不了** | 从静止起步算出 jerk≈8，压过所有收益 |
| `remaining` 用绝对值 | 原地自转被判最优 | 该项占总代价 87%，对同位置候选**无区分度** |
| `velocity_error` 对 `v_max` | 起步阶段永远偏低速 | 加速度窗口每周期只放开 0.08 |
| 跳过第 0 点判离障 | 钻进 `clearance<d_min` 后锁死 | 允许"从合规区走进不合规区" |
| 倒车惩罚按 `|v|` | 终点前 0.379 m 反复微倒车到超时 | 低速倒车只罚 0.048，比 stall 的 0.6 便宜太多 |

### 兜底动作 = 停车（不是"最小风险动作"）

所有候选都不满足约束时，**只执行受限减速**：

* 线速度取 `max(0, v_prev − a_max·dt)`，角速度朝 0 走一步
  `ω_prev − sign(ω_prev)·alpha_max·dt`；
* 若当前位置已 `clearance < body_radius`（既成事实），直接判 `physical_violation`
  并终止任务——停车修不回已发生的穿墙。

为什么不能"选最小风险候选继续走"：任何非零速度都可能把车推进墙体。
实测 hard 档 `min_clearance = 0.371 m < body_radius 0.58 m`（车身穿墙）
却仍被记为"到达"，正是这个旧语义造成的。

为什么不能直接置 `v=0, ω=0`：会造出一次断崖式减速（实测 0.961 → 0 即 9.6 m/s²，
远超 `a_max=0.8`；`ω` 从 −0.448 → 0 即 2.39 rad/s²，超 `alpha_max=2.09`），
让"违反率 0"与曲线自相矛盾。所以兜底也必须在加速度窗口内。

### 指标口径（论文必须声明）

* `constraint_violation_rate_per_period` = 违反周期数 / 总周期数；
* `constraint_violation_rate_per_task` = 任一周期违反即计 1（二值）。

其余：碰撞帧数、最小离障、最小动态间距、到达时间、路径长度、能耗、`a_y` 最大值、
jerk RMS、平均速度、平均绝对角速度。
**主口径声明：本表以"按周期"为主**（反映风险暴露时长），"按任务"作为保守上界并列。

### 接触帧二维分解与三类结论（2026-10-31，`docs/dwa_contact_decomposition.csv`）

接触帧必须**同时**按两个正交维度分解，否则无法写进论文：

1. **成因**：该周期本车是否在运动（`|v| > V_STOPPED_MPS = 0.01 m/s`，即标称速度的 1%）
   → **主动碰撞** / **被动接触**；
2. **几何可行性**：任务瓶颈 `W` 是否 `< 2(R + r_o) = 1.76 m`
   → **几何上不可会车** / **规划器本可避免**。

**会车净宽判据（闭式）**：两圆不接触要求中心距 `≥ R + r_o`；本车中心离墙至少 `R`、
障碍中心离墙至少 `r_o`，故两中心最大横向间距是 `W − R − r_o`。令
`W − R − r_o ≥ R + r_o` 得

```
W_required = 2 (R + r_o) = 2 × (0.58 + 0.30) = 1.76 m
```

`W < 1.76 m` 的通道**几何上不可能完成会车**，此时的接触是**结构性不可避**，
不是规划器放过了某个阈值。该判据与算法、与是否可跟踪都无关。

**真实结果（`frozen_A.yaml`，36 个执行过的动态任务）**：

| | 几何不可避 `W < 1.76 m` | 本可避免 `W ≥ 1.76 m` | 合计 |
|---|---|---|---|
| **本车在动（主动碰撞）** | **0** | **0** | **0** |
| **本车已停（被动接触）** | **61** | **223** | **284** |
| 合计 | 61 | 223 | 284 |

* `|v|` 分箱（接触帧）：`≤0.01 m/s` = **284**，`0.01~0.10` = 0，`0.10~0.30` = 0，
  `>0.30` = 0 —— 全部 284 帧本车都是**完全静止**，结论不随阈值选择而变。
* 「本车已停 **且** `W < 1.76 m`」= **61 帧 = 21.5%**（占全部接触帧）；
  其余 223 帧落在 easy 档（`W ≥ 2.405 m`，走廊足够宽），是**非合作障碍主动扫过
  已停车辆**造成的，需要横向逃离空间或速度规划，不是间距阈值能消掉的。
* 修正前同样的分解是 **主动 1832 / 被动 194**（其中 `W < 1.76` 786 /
  `W ≥ 1.76` 1240）—— 判据过宽时本车会**一边行驶一边重叠**，主动碰撞 1832 帧。

**结论三类（全文不再使用"零碰撞"这一说法）**：

> ① **主动碰撞 = 0 帧**（必须为 0，否则是 bug）；
> ② **被动接触 = 284 帧**（12/36 任务），其中「本车已停 **且** 瓶颈 < 1.76 m」
> 占 **61 帧 = 21.5%**，属几何上不可会车的结构性接触；
> ③ **未完成（超时）= 1 个任务**（hard 档 1/8）。

### 圆心距的两条口径（论文必须声明，2026-10-30 新增）

`min_gap_dynamic_m` 只有预测口径，会**系统性低估**风险：它取自被选中候选的
0.6 s 预测轨迹，而每个周期只执行第一步，停车兜底周期还记 `inf`。因此新增执行口径：

| 列 | 含义 | 用途 |
|---|---|---|
| `min_gap_dynamic_m` | 被选中候选**预测**轨迹上的最小圆心距（兜底周期 = `inf`） | 判据是否生效（修正后饱和在阈值 1.130 m） |
| `min_gap_realized_m` | 执行轨迹与障碍轨迹**逐周期对齐**实测的最小圆心距 | 风险暴露的真实度量（修正前最小 0.007 m） |
| `contact_gap_m` | `body_radius + obstacle_radius_m`（= 0.88 m） | 两圆不接触门槛 |
| `dynamic_contact_periods` | 实际圆心距 `< contact_gap_m` 的周期数 | **动态接触帧数**，与车身穿墙帧分列 |

修正前只报预测口径时，"最小圆心距 0.550 m"看起来只是"贴着阈值"，
而执行口径显示 36 个动态任务里 **26 个**发生过两圆重叠、最小 0.007 m。

**怎么复现"修正前"那一列**：`docs/dwa_metrics_before.csv` 由**临时回退阈值**
产生（把 `core/dwa.py` 里 `required_here = contact_here + required_gap(...)`
改回 `float(radius) + required_gap(...)`，跑一次 `analysis.dwa`，再改回来）。
该回退版在 12 个共享列上与更早一次真正的旧代码运行
（`task_ok`/`reason`/`periods`/`min_gap_dynamic_m`/`fell_back_periods` … 共 80 行）
**逐字段一致**，因此这一列可信。对比命令：

```bash
uv run python -m analysis.dwa_gapfix_compare          # -> docs/dwa_gapfix_compare.csv + 对比图
```

**超出幅度上限**（三档均为 0，说明没有"差一点点"的擦边违反）：
策略裕度 `max(d_min−clearance) = 0`、物理穿墙 `max(body_radius−clearance) = 0`、
动态间距 `max(gap_req−gap) = 0`、`a_y` 超出 `max(a_y−a_max) = 0`。

**指标口径声明（论文必须写）**：

1. **两级安全约束分开统计**：
   * `physical_collision_frames`：`clearance < body_radius = 0.58 m`，**车身穿墙**，
     违反即碰撞、任务失败（`success=False`、`reached_goal=False`）；
   * `policy_violation_periods`：`body_radius <= clearance < d_min = 0.70 m`，
     策略裕度不足，**可降级但必须记录幅度**。
   二者互斥，不能合并计数（早期版本合成一个 `d_min` 判据，导致
   hard 出现 `min_clearance=0.371 < 0.58` 却仍记为"到达 8/8"）。
2. **两条圆心距口径都要报**（见上一节），且 **`min_gap >= body_radius + r_o`
   才等价于"无接触"**：
   * 判据 = `body_radius + r_o + required_gap(δ)`，其中 `required_gap(δ)` 是
     **表面间隙**要求（0.25~0.60 m）；
   * **`>= r_o` 是错的口径**（漏掉车体半径，会把两圆重叠 0.33 m 判成无接触）；
   * 它与 `clearance`（到墙面的距离）不是同一个量纲下的同一个东西，不可混用。
3. **成功判据（2026-10-31 定稿）**：`success = 到达终点 ∧ 无物理违反`。
   **`timeout` 不算成功，成功率 = 到达率**。旧口径把 `timeout` 也算成功
   （语义是"有指令序列且没穿墙"），于是 hard 档打印 `task_ok = 8/8`，
   掩盖了"1 个任务超时未完成"；正确表述是 **「到达 7/8、超时 1/8」**。
   三种结束状态互斥且穷尽：`reached_goal` / `timeout` / 物理违反。
4. **接触帧必须二维分解**（成因 × 几何可行性），三类结论并列：
   ① 主动碰撞（必须 0）、② 被动接触（含「已停 ∧ 瓶颈 < 1.76 m」占比）、
   ③ 未完成（超时）。**不使用"零碰撞"这一说法** —— 车身穿墙帧为 0 只说明
   静态层没被突破，不能代表动态层没有接触。
5. **违反率必须同时报分母**：`0/4271` 是跨全部任务的周期加总，
   单任务的 `58/247 = 23.5%` 是另一个分母；两者都对，但表里必须写清。
6. **布尔率必须配超出幅度**：`a_y` 最大值 0.798 与 0.800 在被布尔化后看起来一样，
   所以同时给 `max(a_y − a_max)`。

### 2c. 与已发表论文的 26% **不可并列对比**（口径声明）

本课题已发表的小论文报告过 **26%** 的能耗优化空间。本框架在真实户型上测到的是
**总能耗 −1.09%、单任务最多 −9.65%**。**两个数字不得并列对比**，因为口径有三处根本差异：

| 维度 | 已发表小论文 | 本框架 |
|---|---|---|
| 地图 | **随机栅格**，高阻地形近似**满铺** | **真实 HouseExpo 户型**，高阻材质按受控面积占比分区（20 个场景实际高阻占比 14%~66%） |
| 能耗模型 | **简化模型**：只有滚阻与坡度项 | **完整模型**：滚阻 + 坡度 + 惯性 + 传动效率 + 电池内阻 + **辅助功率 `P_aux`** |
| `P_aux` 占比 | 0（模型里没有这一项） | 约占参考能耗 **1/3**（15 W / 1 m/s ≈ 15 J/m，实测 `c_rr = 0.03` 时约 23 J/m 地形项） |

**为什么满铺 + 简化模型会放大收益**：能耗 = 地形项 + **与时间成正比的辅助项**。
`P_aux` 项对**所有路线**都按时间等量叠加，因此它不区分"走哪条路"，只会稀释
地形项之间的相对差。去掉它、再把高阻铺满，收益自然被放大。

**量化这条差异**（`docs/energy_gain_groups_summary_paux0.csv`，同一批 60 个任务、
只把 `P_aux` 置 0）：

| 组 | 全模型 Δ中位 [J] | 简化模型 Δ中位 [J] | 全模型 Δ总和 [J] | 简化模型 Δ总和 [J] | 全模型 Δ%中位 | 简化模型 Δ%中位 |
|---|---|---|---|---|---|---|
| 低（< 10%） | 0.000 | 0.000 | 84.60 | **111.21** | 0.0000 | 0.0000 |
| 中（10~40%） | 0.485 | **1.324** | 134.31 | **174.59** | −0.0884 | **−0.5342** |
| 高（> 40%） | 0.975 | 0.971 | 21.36 | **67.11** | −0.1043 | −0.1374 |

* **去掉辅助功率项确实放大收益**：中阻组中位 ×2.7、相对收益 ×6
  （−0.088% → −0.534%），高阻组总和 ×3.1（21.4 → 67.1 J）。
  方向与"`P_aux` 稀释地形影响"的判断一致。
* **但仍然远不到 26%，而且不应该到**：本框架的地图是**真实户型**，高阻材质面积占比
  只有 14%~66%（不是满铺），路线还受几何约束（可行域被压成走廊）。
  已发表论文的 26% 来自"随机栅格 + 高阻近似满铺 + 简化能耗模型"三件事的叠加。
* **结论**：这是**口径对照**，不是"本框架的另一个结果"。论文里引用 26% 时必须同时
  写清它的场景与模型前提，**不得与本框架的数字并列成"我们发现 X%、已发表 Y%"**。

| 软惩罚 w=2 / w=5 | 20 | 11.086 | 472.11 | 0.0000 | 0/20 | 0.0000 | 0.712 |
| **硬约束（本文）** | 20 | 11.086 | 472.11 | **0.0000** | 0/20 | 0.0000 | 0.712 |

* **结论与上一轮一致（地形变化没有翻转它）**：违反率随 w 单调下降
  （0.2821 → 0.0653 → 0.0233 → 0.0144 → 0）。**仅长度**这一列不是单调的
  （w=0 总能耗 10736.4 J、w=0.1 反而 10716.3 J、w=1 收敛到 10827.6 J）：
  软惩罚改变的是路线选择，而不同路线跨的材质分区不同，所以"能耗总量"不必单调 ——
  论文里不要写"能耗随 w 单调上升"。
* 本数据集上 **w ≥ 1 时软惩罚解与硬约束解在 20/20 任务上逐字段相同**，
  没有出现"违反率 > 0 且随 w 下降但永不为 0"的区间。机理：可行路线是**有限个
  同伦类的离散集合**，当 w 超过"最优违反路线"的边际兑换率后，最优点直接跳到合规路线。
  所以正确表述是"**软惩罚的违反率不保证为 0**"，而不是"软惩罚总会留一点违反"：
  w ≤ 0.5 时违反率 1.4%~28.2%、涉及 8~11 个任务，而 w 取多少**没有原理性依据**。
* **物理穿行**这一列是硬约束最直接的证据：w=0 时有 **23.5% 的路程**走在
  `clearance < body_radius = 0.58 m` 的通道里（最小 0.05 m），即规划器会把轮椅
  送进比车体还窄的缝；硬约束下恒为 0。

`feasible_area_ratio`（`env/scene_quality.py::feasible_area_ratio`）的定义：
**场景自由区（`clearance > 0`）中，满足 `clearance >= d_min` 且与锚点（起点）同属一个
连通分量的单元面积占比**（单元等面积，所以就是面积之比）。锚点自身不满足门槛时返回 0，
表示"这个任务在该档不可用"。它不依赖采样次数，因此比"可行任务数"更适合写进论文；
中位数里的 0（例如 1.10 档重采样锚点列）表示过半场景在该档没有任务。

**"可行任务数"的使用限制**：它是 20 个场景上的比例量，受**采样预算**（24 次/场景）与
随机种子影响。表里给出 95% Wilson 得分区间，采样失败会**低估**真实可行性，
所以它是下界性质的证据；写论文时与 `feasible_area_ratio` 搭配使用。

三点解读：

1. **0.58 与 0.70 之间：路径长度/能耗不变，只有离障变**（最小离障 0.740 -> 0.691 -> 0.582）。
   8 邻域栅格上贴着约束边界走不额外付出长度代价，所以放宽 d_min 的收益是**可行域变大**，
   不是路径变短。这一条本身就是第 3 章可写的结论。
2. **0.90 档：固定起终点 8/20，重新采样后 12/20（CI 39–78%）**。原来的"0.90 断崖"
   有一半是假象：4 个 medium 场景的冻结任务在 0.90 下不可用，但同一分量内重新采样后
   仍有中档任务（W = 1.90 m）。剩下 8 个 hard 场景（1.46~1.50 m）在该档**物理上**不存在任务。
   确定性指标同样显示收缩：可行面积占比中位从 0.542（0.70）降到 0.195（0.90）。
3. 1.10 档只剩 8 个 easy 场景（W ≥ 2.10 m > 2 x 1.10 = 2.20 m 附近），与物理预期一致；
   不同档位的路径长/能耗中位数统计的是不同任务集合，**不可直接横向比较**。

### 锚点映射：把场地局部坐标放进户型

ETH/UCY 的坐标属于各自场地（ETH 校园 / 酒店大堂 / 火车站前街道 / UCY 校园），
原点与朝向与 HouseExpo 户型**毫无关系**，所以必须显式声明

```
xy_world = scale * R(rotation_deg) @ xy_local + origin_xy
```

* `scale` **固定 1.0**：数据本身就是米，缩放会连带改变步行速度（第一条纪律：
  不靠缩小数据去"凑"可用率）；
* `rotation_deg` / `origin_xy` 由 `env/pedestrians.py::fit_anchor` 依据**场景几何**
  搜索确定 —— 自由区最大内接矩形定中心，旋转角 5° 网格 × 平移 0.5 m 网格，
  目标函数是"行人圆（半径 `body_radius`）与墙冲突的样本比例"最小。
  给定 (序列, 场景) 与搜索参数，**结果唯一**；逐组合的实际取值见
  `docs/pedestrian_anchor.csv`。
* **性能**：朴素实现单组合 ≈ 72 角度 × 81 平移 × 18 353 行 ≈ 1 亿次逐点运算
  （几十秒）；现在每个角度只旋转一次、平移只做整数格点偏移 + 一次 `np.take`
  变址，实测 **0.98 s**（`students001`，18 353 行）。这是本轮"跑得慢"的主因，
  已在函数 docstring 里写明原因，避免下次再踩。

### 时间对齐与可用性筛选

* **重采样**：数据集帧步长恒为 10、**2.5 fps（0.4 s）**，重采样到 `dt = 0.1 s`
  是**加密**（帧数 = `floor(ΔT/dt) + 1`），不是抽稀；
* **不跨观测空洞插值**：`observation_runs` 按"相邻观测间隔 > 0.6 s"切段，
  插值只在段内进行。**这条是必须的**：ETH 的 `eth.txt` 帧号有 60/70/90 的大步长，
  跨空洞插值会**凭空造出**行人从未走过的直线运动（再被穿墙筛选剔掉，污染统计）；
* **速度**：重采样后的中心差分 + 0.5 s 滑动平均（`velocity_window = 5`）。
  直接对 0.4 s 原始帧做差分会把标注噪声放大 4 倍，而 DWA 的绕行判据用相对运动
  方向 δ，速度方向抖动会让判据在相邻周期反复翻转；
* **三条筛选**（比例同分母 = 连续观测段内重采样后的样本数）：
  ① 出界（栅格之外）剔除；② 穿墙（圆心离墙 `< body_radius`）剔除；
  ③ **连续**穿墙超过 3 个周期 → 该观测段整体丢弃。逐点剔除后按连续可用段切分，
  时间轴出现空洞就断开（否则插值会让行人瞬移穿过被剔除的墙段）。

  **主动碰撞 0 帧**、被动接触 284 帧（其中「已停 ∧ 瓶颈 < 1.76 m」61 帧 = 21.5%）、
  未完成 1 个；`success` 不再把 `timeout` 算成功（hard = 到达 7/8、超时 1/8）。

详细对比与复现方式见「DWA 局部规划 → 接触帧二维分解 / 修正前后对比」。

**第 6.7 项（2026-11-06）只做结果生成与两个可选开关**，`core/` 里唯一改动是
`AStarParams` 新增 `enforce_dmin` / `soft_penalty_weight`（默认值 = 既有行为，
基准值测试锁定）。三条结论：① 约束化 A* 用 **+0.58% 长度**换来 11 个贴墙任务
全部合规（基线违反率中位 38.3%）；② 当前场景集 **(长度, 能耗) 前沿全部退化为单点**，
ESA* 与仅长度 A* 输出完全相同；③ 软惩罚的违反率随 w 单调下降，但**没有任何 w
能保证 0 违反**（w=0 时有 23.5% 的路程走在比车体还窄的通道里），硬约束恒为 0。

**第 6.8 / 6.9 项（2026-11-07）修掉了 ② 的根因**：材质空间分布改成**受控实验因子**
（真实户型几何 + 按受控面积占比叠加的材质分区），`c_rr` 覆盖论文材质表的
0.015 / 0.03 / 0.04 / 0.06（跨度 1.67 → **4 倍**），三档分布见「受控材质因子」一节。
重跑第 3 章后：**ESA\* 与仅长度 A\* 在 10/20 任务上不同（总能耗 −1.09%，
单任务最多 −9.65%）**、**(长度, 能耗) 前沿在 4/20 任务上出现多点**（最多 7 点）。
**仍单点的 16 个任务是几何原因**（easy/medium 瓶颈 1.7~6.7 m、只剩一条必经路线，
同伦类候选不存在），不是参数没调够；附加多端点对任务把多点任务做到 11/60，
且 easy/medium/hard 三档都有。

把 ETH/UCY 排到 DWA 之后，理由：**行人轨迹是 DWA 的输入**。DWA 落地后，
`ObstacleTrack` 已经是"显式位置-时间轨迹"，把数据集读成两列 `(t, xy)` 即可接入，
DWA 侧不需要改动；这样行人轨迹才能验证"绕行可行性判据"这类主张。

B 样条里程碑留下的两个入口给 DWA：

* `core/bspline.SmoothPath` 直接给出 `xy / yaw / s / curvature`，DWA 的参考轨迹与
  曲率限速（`v ≤ min(v_max, sqrt(a_y_max / |κ|))`）可以直接消费，不需要再算一遍曲率；
* `SmoothingReport` 的 `status` / `reason` / `inserted_points` 已经把"这条任务能不能
  平滑"结构化了，第 4 章做动态层时可用它筛"静态层已经贴墙"的任务，避免把回退任务
  ｜
  的失败错误归因给 DWA。

## 性能与可复现的工程约定（2026-11-08 补充）

本项目全部实验在 CPU 上跑，几个"看起来卡住"的坑已经定位清楚并写了原因，后续不要再踩：

| 位置 | 坑 | 量级与做法 |
|---|---|---|
| `env/terrain_partition.py::quadtree_zones` | 递归二分的分区数随格子边长平方增长 | 真实场景 200~1500 个分区，正常 |
| `env/pedestrians.py::fit_anchor` | 朴素实现把整条序列在每个 (角度, 平移) 上重新旋转+查表 | `students001` 18 353 行 × 72 角度 × 81 平移 ≈ **1 亿次**逐点运算；改为"每角度旋转一次 + 平移只做整数格点偏移 + 一次 `np.take` 变址"后 **0.98 s** |
| `env/pedestrians.py::load_sequence` | 同一序列被 20 个场景各解析一次 | 加进程内缓存（键含 mtime）：首次 0.048 s、命中 0.0005 s |
| `core/dwa.py::evaluate_candidate` | 对每个候选**逐个行人**调用 numpy 标量运算，成本 ∝ 候选数 × 行人数 × 周期数 | 单个 episode 实测：122 人 = 337 s、93 人 = 76 s、**12 人 = 25 s**。因此**拥挤度是必须受控的实验因子**（`config/pedestrian_sequences.yaml::task_design`），不是"越挤越好" |
| `analysis/pedestrians.py::main` | 任务按 FIFO 下发，easy 做完的 worker 空转等 hard | hard 场景路径 20 m、easy 8 m，单 episode 成本差 2~3 倍；改为**按预估成本降序下发**（LPT），总时长从 >90 min 压到 ~40 min |

**报告纪律**：任何"用了多少算力/砍了多少数据"的取舍都要写进结果表
（例如 `pedestrians_in_window` 与 `pedestrians_crowd_dropped` 必须并列给出），
不允许只报对自己有利的一侧。

每个里程碑都要求出图，验收方式是看图，不看代码。
